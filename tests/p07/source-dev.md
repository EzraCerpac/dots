# Source-dev scenarios

The legacy suite has 99 top-level cases at oracle v0.4.0, `f5c8a0e`. The Rust integration suite runs the public executable selected by Q-01 World.

The oracle requires a GitHub-shaped origin. Its private fixture checkout redirects that literal origin to the World bare repository via a local Git rewrite. The Rust fixture gives the same bare repository a literal matching `file://` origin. Both restrict Git to file transport. Each fixture uses private configuration, home, state, temporary files and a restricted tool path.

The [P-07 fixture adapter](isolation.rs) gets the executable from Q-01's `World::dots()`.
It sets private XDG, agent, Git and mise paths before starting either fixture setup or a command under test.
JJ uses Q-01's fixture config and Git transports allow only local files.

The integration suite contains 109 unchanged and 13 new tests. Each of the 99 original cases has an executable counterpart or a documented gap. Split rows preserve all externally observable portions listed below. Unchanged counts include parameterized branches split into independent tests.

The Q-01 owner accounts separately for `test_dots_contract.py`.
That suite owns the legacy public sync and replay test, the updater forwarding and stage tests,
and the legacy standalone stage attachment test.
P-07's counts cover its four JavaScript suites and the new standalone sync cancellation outcome.
